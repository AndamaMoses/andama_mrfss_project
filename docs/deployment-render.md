# Deploy the demo on Render

GitHub stores the code; Render runs the Flask app and gives you an HTTPS URL.
GitHub Pages cannot host this application because it needs a Python server and a
SQLite database.

The repository ships [`render.yaml`](../render.yaml), a Render Blueprint for a
free demo service:

| Setting | Value |
|---|---|
| Branch | `feature/packaging` (the branch that contains this file) |
| Build | `python -m pip install -r requirements-prod.txt` |
| Start | `gunicorn --preload --workers 1 --threads 4 --bind 0.0.0.0:$PORT wsgi:app` |
| Health check | `/login` |
| Plan | Core |
| Demo data | 10 products, 5 receipts, 3 synthetic patients, 2 expenses |
| Database | SQLite on the service's local disk |

## What the first boot does

`wsgi.py` runs the idempotent bootstrap before Gunicorn forks:

1. Creates the schema and runs pending migrations.
2. Creates `admin` and `grace` with the passwords you provide in Render.
3. Seeds the Core plan (Dashboard, Point of Sale, Inventory).
4. With `DEMO_SEED=1`, inserts synthetic demo data — only when the products
   table is empty. Real shop data is never touched.

## Before you start

- A [Render account](https://dashboard.render.com/register).
- Access to the GitHub repository as its owner.
- Two strong passwords for the demo accounts (12+ characters).

## Deploy with the Blueprint

1. Sign in to Render and open **Blueprints**.
2. Choose **New Blueprint Instance**.
3. Connect GitHub if prompted, then select
   `AndamaMoses/andama_mrfss_project`.
4. Select the branch `feature/packaging` (or `main` after you merge it there).
   Render reads `render.yaml` from the selected branch.
5. Confirm the service name and region, then apply the Blueprint.
6. When Render prompts for environment variables, enter:
   - `ADMIN_PASSWORD` — the Shop Owner password.
   - `STAFF_PASSWORD` — the Sales Agent (`grace`) password.
   - `SUPPORT_WHATSAPP` — optional, for example `+256776102744`.
7. Wait for the first deploy to finish, then open the `onrender.com` URL.
8. Sign in as `admin` with the password you entered.

`SECRET_KEY` is generated by Render and never stored in the repository.

## Post-deploy smoke test

1. The dashboard shows today's synthetic sales, low stock, expiries, and refills.
2. **Sell / POS** lists ten products and completes a test sale.
3. **Stock & Expiry** shows the expired Omeprazole batch and low Cetirizine,
   Ibuprofen, and ORS stock.
4. **Apps & Add-ons** shows the Core plan; Pro, Growth, and Tender are locked.
5. Sign out and back in; the session survives.

## Free-tier behaviour

The free plan has an ephemeral filesystem and spins down after inactivity:

- A restart or redeploy resets the database and reseeds the synthetic demo.
- The first request after a spin-down can take 30–60 seconds.
- Anything a visitor enters is disposable. That is intentional for a demo.

### Keep data with a persistent disk

Upgrade the service to a paid instance type, then attach a disk in
**Settings → Disks**:

| Setting | Value |
|---|---|
| Mount path | `/var/data` |
| Size | 1 GB |

Add these environment variables and redeploy:

```text
DRUGSHOP_DB=/var/data/drugshop.db
DRUGSHOP_UPLOADS=/var/data/uploads
```

The demo seed runs once on the new empty disk and then persists. Keep the
service at one instance; SQLite and local uploads are not shared across
instances.

## Updating the deployment

Push to the branch the Blueprint tracks. Render redeploys automatically. The
schema bootstrap and migrations are safe to run on every boot.

## Changing the plan

The plan is chosen on first boot. To change it later, open a Render Shell
(paid plans) and run:

```bash
flask --app wsgi plan set pro --actor "operator"
flask --app wsgi plan show
```

On the free plan, redeploy with a different `DRUGSHOP_BUNDLE` value. Because the
free filesystem is ephemeral, the fresh database seeds the new plan on boot.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Build fails resolving Python | Set `PYTHON_VERSION` to a version Render currently offers, such as `3.12.8`. |
| `SECRET_KEY must be set` | Add `SECRET_KEY` to the service environment (the Blueprint generates it). |
| Sign-in appears to succeed but redirects to login | Use the HTTPS `onrender.com` URL. Production cookies are `Secure`. |
| 502 on first request | The free instance is waking up; retry after a minute. |
| Demo data disappeared | Expected on the free plan; configure a persistent disk. |

## Security notes

- Never enable `DEMO_SEED` against a database with real patient or sales data.
- Set strong `ADMIN_PASSWORD` and `STAFF_PASSWORD` values; the development
  defaults are only for local use.
- Do not upload real patient records or supplier documents to a public demo.
- For a real shop, use a paid instance, a persistent disk, backups, and the
  [onboarding](onboarding-runbook.md) and [rollback](rollback-runbook.md)
  runbooks.
